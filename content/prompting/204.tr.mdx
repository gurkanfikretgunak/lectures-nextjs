### 1.1. Net Talimatlar

Kişilikleri ve kısıtlamaları tanımlayarak belirsizliği ortadan kaldırın.

**Net Talimatlar Olmadan:**

```text
❌ Kötü: Veri işlemek için bir fonksiyon yazın.
```

**Net Talimatlarla:**

```text
✅ İyi: Veri işleme konusunda uzman kıdemli bir Python geliştiricisisiniz.

Şunları yapan bir fonksiyon yazın:
- Girdi olarak sözlük listesi alır
- 'status' 'inactive' olan girişleri filtreler
- 'created_at' tarihine göre sıralanmış liste döndürür (en yeni önce)
- Boş listeleri zarifçe işler
- Tip ipuçları ve docstring içerir
- Girdi liste değilse ValueError yükseltir

Fonksiyon imzası:
def process_active_records(records: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
```

**Kişilik Tanımı:**

```text
Şu konularda 15+ yıl deneyime sahip uzman bir yazılım mimarısınız:
- Mikroservis mimarisi
- Olay güdümlü sistemler
- Bulut-native uygulamalar (AWS, GCP, Azure)
- Konteyner orkestrasyonu (Kubernetes, Docker Swarm)

Göreviniz: Ölçeklenebilir bir bildirim sistemi tasarlayın.
```

**Kısıtlama Tanımı:**

```text
Kısıtlamalar:
- TypeScript kullanmalı
- SOLID prensiplerini takip etmeli
- Maksimum fonksiyon uzunluğu: 50 satır
- Hata yönetimi içermeli
- Test edilebilir olmalı (bağımlılık enjeksiyonu)
- Performans: Saniyede 10K istek işlemeli
```

### 1.2. Referans Metinler

Model halüsinasyonlarını önlemek için kod parçacıkları referans olarak sağlayın.

**Referans Olmadan:**

```text
❌ Kötü: Mevcut kullanıcı kimlik doğrulamamıza benzer bir fonksiyon yazın.
```

**Referansla:**

```text
✅ İyi: Mevcut kullanıcı kimlik doğrulama kalıbımıza benzer bir fonksiyon yazın:

Referans uygulama:
\`\`\`python
def authenticate_user(email: str, password: str) -> Optional[User]:
    """
    E-posta ve şifre ile kullanıcıyı doğrula.
    
    Args:
        email: Kullanıcı e-posta adresi
        password: Düz metin şifre
        
    Returns:
        Doğrulanmışsa User nesnesi, aksi halde None
    """
    user = UserRepository.find_by_email(email)
    if user and bcrypt.checkpw(password.encode(), user.password_hash.encode()):
        return user
    return None
\`\`\`

Şimdi aynı kalıbı takip ederek API anahtarı kimlik doğrulaması için benzer bir fonksiyon yazın.
```

**Kod Bağlamı:**

```text
Kod tabanından bağlam:
- Dosya: src/auth/strategies/jwt.ts
- Kalıp: Token tabanlı kimlik doğrulama
- Hata yönetimi: Özel AuthError sınıfı
- Loglama: Winston logger

Bu kalıbı takip ederek yeni bir OAuth2 stratejisi yazın.
```

```python
# Kıyaslama test durumları
test_cases = [
    {
        "input": "Faktöriyel hesaplayan bir fonksiyon yazın",
        "expected_output": "def factorial(n: int) -> int: ...",
        "criteria": [
            "Tip ipuçları var",
            "Uç durumları işler (0, negatif)",
            "Docstring içerir",
            "Özyineleme veya yinelemeyi doğru kullanır"
        ]
    },
    {
        "input": "E-posta doğrulayan bir fonksiyon yazın",
        "expected_output": "def validate_email(email: str) -> bool: ...",
        "criteria": [
            "Regex veya uygun doğrulama kullanır",
            "Uç durumları işler",
            "Boolean döndürür",
            "Hata yönetimi içerir"
        ]
    }
]

# Prompt performansını değerlendir
def evaluate_prompt(prompt_template, test_cases):
    results = []
    for test in test_cases:
        response = llm.generate(prompt_template.format(input=test["input"]))
        score = evaluate_response(response, test["criteria"])
        results.append({
            "test": test["input"],
            "score": score,
            "passed": score >= 0.8
        })
    return results
```

```python
def select_model(task_complexity: str, file_count: int, reasoning_depth: str) -> str:
```

### 3.1. Gömme Mantığı

**Gömme Nasıl Çalışır:**

```python
# Örnek: Kod gömme
code_snippets = [
    "def calculate_total(items): return sum(item.price for item in items)",
    "def compute_sum(numbers): return sum(numbers)",
    "def authenticate_user(email, password): ...",
    "def login_user(username, password): ..."
]

# Gömme sonrası, vektörler şöyle görünebilir:
# calculate_total: [0.1, 0.8, 0.3, ...] (1536 boyut)
# compute_sum:     [0.1, 0.7, 0.3, ...] (calculate_total'e benzer)
# authenticate_user: [0.9, 0.2, 0.1, ...] (calculate_total'den farklı)
# login_user:      [0.9, 0.2, 0.1, ...] (authenticate_user'e benzer)

# Semantik benzerlik = vektörler arasındaki kosinüs benzerliği
```

```text
Copilot bulur:
- auth.ts: Kullanıcı kimlik doğrulama mantığı
- middleware.ts: Auth middleware
- types.ts: Kullanıcı tip tanımları

Sonra bu bağlamı kullanarak yanıt oluşturur.
```

### 3.2. Semantik Arama Optimizasyonu

Kodun ne yaptığını açıklayan tutarlı isimlendirme yoluyla AI'nın doğru kod bloklarını bulma başarı oranını artırın.

**Kötü İsimlendirme (Düşük Başarı Oranı):**

```typescript
// ❌ Kötü: Belirsiz isimler semantik aramaya yardımcı olmaz
function xyz(a: any, b: any): any {
  // ...
}

function process(data: any): any {
  // ...
}

function helper(arr: any[]): any {
  // ...
}
```

**İyi İsimlendirme (Yüksek Başarı Oranı):**

```typescript
// ✅ İyi: Açıklayıcı isimler semantik aramayı iyileştirir
function calculateUserOrderTotal(orderItems: OrderItem[]): number {
  // ...
}

function validateUserEmailFormat(email: string): boolean {
  // ...
}

function filterActiveUsers(users: User[]): User[] {
  // ...
}
```

**İsimlendirme En İyi Uygulamaları:**

| Yön | Kötü | İyi | Neden |
|--------|------|------|-----|
| Fonksiyon İsimleri | `process()` | `calculateOrderTotal()` | Eylem + nesneyi açıklar |
| Değişken İsimleri | `data` | `userOrders` | Spesifik ve anlamlı |
| Tip İsimleri | `Item` | `OrderItem` | Net domain bağlamı |
| Dosya İsimleri | `utils.ts` | `order-utils.ts` | Amacı belirtir |

**Semantik Arama Örneği:**

```text
Sorgu: "Kargo maliyetlerini nasıl hesaplıyoruz?"

İyi isimlendirme ile:
✅ Bulur: calculateShippingCost(), getShippingRates(), computeDeliveryFee()

Kötü isimlendirme ile:
❌ Bulur: process(), calculate(), compute() (çok genel, birçok yanlış pozitif)
```

### 3.3. Gömme için Kod Dokümantasyonu

İyi dokümante edilmiş kod semantik arama doğruluğunu artırır.

**Minimal Dokümantasyon:**

```typescript
// ❌ Kötü: Gömme için bağlam yok
function calculate(x: number, y: number): number {
  return x * y + 10;
}
```

**Zengin Dokümantasyon:**

```typescript
// ✅ İyi: Zengin bağlam semantik aramayı iyileştirir
/**
 * Temel fiyat ve kargo ücreti dahil toplam sipariş maliyetini hesaplar.
 * 
 * @param basePrice - Sipariş öğelerinin temel fiyatı
 * @param shippingFee - Kargo ücreti (varsayılan: $10)
 * @returns Toplam sipariş maliyeti
 * 
 * @example
 * const total = calculateOrderTotal(100, 10); // 110 döndürür
 */
function calculateOrderTotal(basePrice: number, shippingFee: number = 10): number {
  return basePrice + shippingFee;
}
```

### 4.1. Standart Slash Komutları

**/fix Komutu:**

```text
Kullanım: /fix [açıklama]

Örnekler:
/fix Bu fonksiyondaki tip hatasını düzelt
/fix Null pointer istisnasını işle
/fix Bu veritabanı sorgusunu optimize et

En İyi Uygulamalar:
- Ne düzeltileceği konusunda spesifik olun
- Varsa hata mesajlarını dahil edin
- Beklenen davranışı belirtin
```

**/explain Komutu:**

```text
Kullanım: /explain [kod veya kavram]

Örnekler:
/explain Bu kimlik doğrulama middleware'i nasıl çalışır?
/explain useMemo ve useCallback arasındaki fark nedir?
/explain Bu algoritmayı adım adım açıkla

En İyi Uygulamalar:
- Açıklama seviyesi isteyin (başlangıç/orta/ileri)
- Gerekirse örnekler isteyin
- İlgili kavramları sorun
```

**/tests Komutu:**

```text
Kullanım: /tests [fonksiyon veya bileşen]

Örnekler:
/tests Bu fonksiyon için birim testleri yaz
/tests Bu API endpoint'i için entegrasyon testleri oluştur
/tests Uç durumları kapsayan test durumları oluştur

En İyi Uygulamalar:
- Test çerçevesini belirtin (Jest, Vitest, vb.)
- Kapsam gereksinimlerinden bahsedin
- Test edilecek uç durumları dahil edin
```

**/terminal Komutu:**

```text
Kullanım: /terminal [komut veya görev]

Örnekler:
/terminal Bağımlılıkları nasıl kurarım?
/terminal Git durumunu kontrol eden komut nedir?
/terminal Tüm TypeScript dosyalarını bulmak için komut oluştur

En İyi Uygulamalar:
- İlgiliyse işletim sistemini belirtin
- Shell'den bahsedin (bash, zsh, PowerShell)
- Komutun açıklamasını isteyin
```

### 4.2. Özel Komutlar

Kurumsal çıktı formatlarını standartlaştırmak için `.github/copilot-instructions.md` içinde özel komutlar tanımlayın.

**Özel Komut Tanımı:**

```markdown
# Özel Slash Komutları

## /doc
Standart formatımızı takip ederek dokümantasyon oluşturun:
- Tiplerle fonksiyon imzası
- Parametre açıklamaları
- Dönüş değeri açıklaması
- Kullanım örnekleri
- Hata koşulları
- İlgili fonksiyonlar

Örnek:
/doc calculateTotal() için dokümantasyon yaz

## /refactor
Standartlarımızı takip ederek kodu yeniden düzenleyin:
- > 50 satırsa fonksiyonları çıkar
- Açıklayıcı değişken isimleri kullan
- Tip ipuçları ekle
- SOLID prensiplerini takip et
- Geriye dönük uyumluluğu koru

Örnek:
/refactor Bu fonksiyonu daha modüler hale getir

## /review
Kod inceleme kontrol listesi:
- [ ] Tip güvenliği
- [ ] Hata yönetimi
- [ ] Performans değerlendirmeleri
- [ ] Güvenlik etkileri
- [ ] Test kapsamı
- [ ] Dokümantasyon

Örnek:
/review Bu pull request'i incele

## /security
Güvenlik denetimi kontrol listesi:
- [ ] Girdi doğrulama
- [ ] SQL injection önleme
- [ ] XSS koruması
- [ ] Kimlik doğrulama/Yetkilendirme
- [ ] Hassas veri işleme
- [ ] Hız sınırlama

Örnek:
/security Bu kimlik doğrulama kodunu denetle
```

**İş Akışı Entegrasyonu:**

