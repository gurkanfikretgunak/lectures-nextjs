### Example Output

When using the prompt above, here is an example review output:

**Code to Review:**
```python
def calculate_average(numbers):
    total = 0
    for n in numbers:
        total = total + n
    return total / len(numbers)
```

**Review Output:**

> #### Critical Issues
>
> 1. **Division by zero**: If `numbers` is empty, `len(numbers)` is 0, causing `ZeroDivisionError`
> 2. **Type handling**: No validation that `numbers` is iterable or contains numeric values
>
> #### Style & Best Practices
>
> 1. Use built-in `sum()` function instead of manual loop
> 2. Missing type hints and docstring
> 3. Variable name `n` is not descriptive
>
> #### Performance
>
> 1. Current: O(n) time, O(1) space - acceptable
> 2. Could use generator if dealing with large datasets
>
> #### Security
>
> 1. No input validation - could raise unexpected exceptions

#### Suggested Improvements

```python
from typing import List, Union

def calculate_average(numbers: List[Union[int, float]]) -> float:
    """
    Calculate the average of a list of numbers.
    
    Args:
        numbers: List of numeric values
        
    Returns:
        The average of the numbers
        
    Raises:
        ValueError: If the list is empty
        TypeError: If the list contains non-numeric values
    """
    if not numbers:
        raise ValueError("Cannot calculate average of empty list")
    
    if not all(isinstance(n, (int, float)) for n in numbers):
        raise TypeError("All elements must be numeric")
    
    return sum(numbers) / len(numbers)
```

### Results

The structured prompt produces comprehensive code reviews with:

1. **Identified edge cases**: Empty list handling, type validation
2. **Style improvements**: Using `sum()`, type hints, docstrings
3. **Performance optimizations**: Algorithm efficiency analysis
4. **Security considerations**: Input validation and error handling
5. **Refactored code examples**: Complete solutions with explanations

## Prompt Engineering Best Practices

### 1. Be Specific

**Bad:**
```text
Summarize this document.
```

**Good:**
```text
Create a 200-word executive summary of this document focusing on 
key decisions, financial implications, and action items. Use 
bullet points for main ideas.
```

### 2. Provide Examples

**Bad:**
```text
Extract dates from the text.
```

**Good:**
```text
Extract dates from the text and format them as YYYY-MM-DD.

Example:
Input: "The meeting is on March 15th, 2024"
Output: "2024-03-15"

Text: {text}
```

### 3. Use Structured Output

**Bad:**
```text
Review this code.
```

**Good:**
```text
Review this code and provide feedback in this format:

## Bugs
[List bugs]

## Style Issues
[List style issues]

## Suggestions
[Provide suggestions]

Code: {code}
```

### 4. Set Constraints

**Bad:**
```text
Write a summary.
```

**Good:**
```text
Write a summary that:
- Is exactly 150 words
- Uses simple language (8th grade level)
- Includes at least 3 key points
- Ends with a conclusion

Document: {document}
```

### 5. Include Role and Context

**Bad:**
```text
Translate this text.
```

**Good:**
```text
You are a professional translator with expertise in technical 
documentation. Translate this text from English to Spanish, 
maintaining technical accuracy and preserving code examples.

Text: {text}
```

## Common Prompt Patterns

| Pattern | Use Case | Example |
|---------|----------|---------|
| Role + Task | Expert analysis | "You are a senior developer. Review this code..." |
| Few-Shot Learning | Consistent format | Provide 2-3 examples before the task |
| Chain of Thought | Complex reasoning | "Think step by step: 1) ... 2) ..." |
| Output Format | Structured data | "Output as JSON with fields: ..." |
| Constraints | Quality control | "Maximum 200 words, use simple language" |
| Iterative Refinement | Quality improvement | Generate → Review → Improve |

## Key Takeaways

| Technique | Use Case | Benefit |
|-----------|----------|---------|
| Role Assignment | Code Review, Translation | Expert-level analysis |
| Structured Output | Data Extraction, Classification | Consistent format |
| Guidelines & Constraints | Summarization, Generation | Quality control |
| Examples (Few-Shot) | Complex tasks | Better accuracy |
| Chain of Thought | Reasoning tasks | Transparent process |
| Prompt Chaining | Multi-step tasks | Better organization |
| Iterative Refinement | Content generation | Higher quality |

## Summary

Effective prompt engineering requires:

- **Clarity**: Be specific about what you want
- **Structure**: Use clear formatting and organization
- **Context**: Provide relevant background information
- **Examples**: Show what good output looks like
- **Constraints**: Set boundaries for quality control
- **Iteration**: Refine prompts based on results

These study cases demonstrate how structured prompts with clear instructions, context, output formats, and examples lead to significantly better AI responses. The key is to think about the task from the AI's perspective and provide all the information needed to produce the desired output.
