## Few-shot Prompting: Golden Standard Code Examples

Few-shot prompting enables the model to copy your style by providing your project's "golden standard" code examples to the LLM as context.

### How Few-shot Prompting Works

<Mermaid chart={`
flowchart LR
    Examples[Golden Standard Examples] --> Context[Create Context]
    Context --> LLM[Send to LLM]
    LLM --> Output[Style-Consistent Output]
`} />

### Basic Few-shot Example

```python
few_shot_basic = """
Write a new function following these examples:

Example 1:
\`\`\`python
def calculate_total(items):
    \"\"\"
    Calculate total price of items.
    
    Args:
        items: List of items with 'price' key
        
    Returns:
        float: Total price
    \"\"\"
    return sum(item['price'] for item in items)
\`\`\`

Example 2:
\`\`\`python
def filter_by_category(products, category):
    \"\"\"
    Filter products by category.
    
    Args:
        products: List of product dicts
        category: Category name to filter by
        
    Returns:
        list: Filtered products
    \"\"\"
    return [p for p in products if p.get('category') == category]
\`\`\`

Now write a function in similar style:
- Function name: `get_user_orders`
- Parameters: user_id, status (optional)
- Add description, use type hints
"""
```

### Teaching Project Style

```python
project_style_few_shot = """
Learn our project's code style:

Example 1 - Error Handling:
\`\`\`python
async def fetch_user_data(user_id: int) -> User:
    try:
        async with db.transaction():
            user = await User.get(user_id)
            if not user:
                raise NotFoundError(f"User {user_id} not found")
            return user
    except DatabaseError as e:
        logger.error(f"Database error fetching user {user_id}: {e}")
        raise ServiceError("Failed to fetch user data") from e
\`\`\`

Example 2 - Service Layer Pattern:
\`\`\`python
class UserService:
    def __init__(self, repo: UserRepository):
        self.repo = repo
    
    async def create_user(self, data: UserCreate) -> User:
        # Validation
        if await self.repo.exists(email=data.email):
            raise ConflictError("Email already exists")
        
        # Business logic
        hashed_password = hash_password(data.password)
        user_data = {**data.dict(), "password": hashed_password}
        
        # Persistence
        return await self.repo.create(user_data)
\`\`\`

Example 3 - API Endpoint:
\`\`\`python
@router.post("/users", response_model=UserResponse)
async def create_user(
    data: UserCreate,
    service: UserService = Depends(get_user_service)
):
    try:
        user = await service.create_user(data)
        return UserResponse.from_orm(user)
    except ConflictError as e:
        raise HTTPException(status_code=409, detail=str(e))
\`\`\`

Write a new ProductService and endpoint following this style.
"""
```

### Domain-Specific Few-shot Examples

```python
domain_few_shot = """
Code examples for e-commerce domain:

Example 1 - Order Processing:
\`\`\`python
class OrderProcessor:
    async def process_order(self, order: Order) -> OrderResult:
        # 1. Inventory check
        if not await self.check_inventory(order.items):
            return OrderResult.failed("Insufficient inventory")
        
        # 2. Payment processing
        payment_result = await self.payment_service.charge(
            order.total_amount,
            order.payment_method
        )
        if not payment_result.success:
            return OrderResult.failed("Payment failed")
        
        # 3. Order creation
        order = await self.order_repo.create(order)
        
        # 4. Inventory update
        await self.update_inventory(order.items)
        
        # 5. Notification
        await self.notify_user(order.user_id, order.id)
        
        return OrderResult.success(order)
\`\`\`

Example 2 - Price Calculation:
\`\`\`python
class PriceCalculator:
    def calculate_total(
        self,
        items: List[CartItem],
        discount_code: Optional[str] = None
    ) -> PriceBreakdown:
        subtotal = sum(item.price * item.quantity for item in items)
        
        # Apply discount
        discount = 0
        if discount_code:
            discount = self.discount_service.apply(
                discount_code,
                subtotal
            )
        
        # Calculate tax
        tax = subtotal * self.tax_rate
        
        # Shipping
        shipping = self.shipping_service.calculate(items)
        
        total = subtotal - discount + tax + shipping
        
        return PriceBreakdown(
            subtotal=subtotal,
            discount=discount,
            tax=tax,
            shipping=shipping,
            total=total
        )
\`\`\`

Write a ShoppingCartService following these patterns.
"""
```

### Test-Driven Few-shot Examples

```python
test_driven_few_shot = """
Test-first approach examples:

Example 1:
\`\`\`python
# Test
def test_calculate_discount():
    calculator = DiscountCalculator()
    assert calculator.calculate(100, "SAVE10") == 90
    assert calculator.calculate(100, "INVALID") == 100

# Implementation
class DiscountCalculator:
    def calculate(self, amount: float, code: str) -> float:
        discounts = {"SAVE10": 0.1, "SAVE20": 0.2}
        discount_rate = discounts.get(code, 0)
        return amount * (1 - discount_rate)
\`\`\`

Example 2:
\`\`\`python
# Test
async def test_user_registration():
    service = UserService(mock_repo)
    user = await service.register("test@example.com", "password123")
    assert user.email == "test@example.com"
    assert user.password != "password123"  # Should be hashed

# Implementation
class UserService:
    async def register(self, email: str, password: str) -> User:
        hashed = hash_password(password)
        return await self.repo.create(email=email, password=hashed)
\`\`\`

Write an EmailValidator service using test-first approach.
"""
```

## Active Prompting: Question-Answer Loop

Active Prompting establishes a "question-answer" loop that enables the LLM to ask you questions and resolve uncertainties for complex problems.

### Active Prompting Architecture

<Mermaid chart={`
flowchart TB
    Problem[Complex Problem] --> LLM[LLM Analyzes]
    LLM --> Questions[Identify Uncertainties]
    Questions --> Q1[Question 1]
    Questions --> Q2[Question 2]
    Questions --> Q3[Question 3]
    
    Q1 --> Answer1[User Answers]
    Q2 --> Answer2[User Answers]
    Q3 --> Answer3[User Answers]
    
    Answer1 --> Refine[Refine Solution]
    Answer2 --> Refine
    Answer3 --> Refine
    
    Refine --> Solution[Final Solution]
`} />

### Basic Active Prompting Example

```python
active_prompting_basic = """
Design an authentication system.

But first, I need to ask you questions to resolve uncertainties:

1. Which authentication method do you want to use?
   - Email/Password
   - OAuth (Google, GitHub, etc.)
   - JWT tokens
   - Session-based

2. What are the password requirements?
   - Minimum length?
   - Special character requirement?
   - Uppercase/lowercase requirement?

3. How long should Token/Session be?
   - Access token: ?
   - Refresh token: ?
   - Session timeout: ?

4. Is multi-factor authentication (MFA) required?

5. Rate limiting requirements?
   - Login attempts per minute?
   - Password reset attempts?

Please answer these questions so I can design the optimal solution.
"""
```

```python
architecture_active = """

   - CI/CD pipeline requirements?

Answer these questions so I can design the optimal architecture.
"""
```

## Summary

What you learned in this lecture:

- **Few-shot Prompting**: Using your project's "golden standard" code examples to make LLM learn your style
- **Active Prompting**: Resolving uncertainties through question-answer loops for complex problems
- **Combined Approach**: Using both techniques together for both style consistency and correct solution guarantee

With these techniques:
- LLM learns your project's code style
- Produces interactive solutions for complex problems
- Proactively resolves uncertainties
- Increases code quality and consistency
